# 装置仿真稳定性检查报告

检查对象：`InvertedTriplePendulum-v0`（小车 + 三连杆倒立摆）
环境：MuJoCo 3.14.0 / Gymnasium 1.3.0 / Python 3.11.2，`frame_skip=5`，物理步长 `0.01 s`（控制周期 `0.05 s`，20 Hz）
可复现脚本：`tools/stability_check.py`（`--quick` 跳过时间步边界扫描）

---

## 0. 结论速览

| 层面 | 结论 |
|------|------|
| 物理仿真数值稳定性 | **通过**，9/9 项检查全绿，无能量注入、无 NaN、时间步有 6× 裕度 |
| 积分器选型 | **正确**，RK4 实测 4 阶；同 dt 下比 MuJoCo 的 Euler/implicit 系（1 阶）精度高约 1140 倍 |
| 刚体/几何建模 | **正确**，精确竖直平衡点零漂移，无伪不对称注入 |
| **reset 分布（本次改动）** | **不成立**，61.2% 的初始状态在第一步就判负，训练信号被污染 |
| **训练/评估口径** | **已分叉**，`eval_sac.py` 20/20 FAIL（不是策略问题，是口径问题） |
| **`reset_noise_scale` 参数** | **已失效**（死参数），4 种取值实测结果完全相同 |
| `reset_model` 缩进 | **阻断性语法错误，已修复** |

**一句话**：仿真内核没问题，问题全部集中在刚改的 `reset_model` 及其连带的口径分叉。它的 40% 下垂 + 30% 大角度分支绝大多数落在终止判据之外，episode 走不到第 2 步；而 `sac_train.py` 用 `termination_height=-999` 绕过之后，评估脚本却没跟着改，于是评估全盘报错。

## 2. reset 分布问题（核心）

### 2.1 实测数据

5000 次 `reset`，统计初始 tip 高度：

```
reset tip_z: min=-1.800  median=1.029  max=1.800
初始 tip_z <= termination_height(1.5) 的比例 : 61.2%
初始 tip_z <= 0（垂到小车以下）的比例       : 41.4%

分支            n      tip_z 区间             已经处于跌倒状态
近顶部 (±0.15)  1472   [ 1.721,  1.800]       0.0%
大角度 (±1.2)   3528   [-1.800,  1.793]      86.7%
```

2000 次「reset 后零动作走一步」：

```
第 1 步就 terminated 的比例 : 60.6%
第 1 步奖励: min=-12.961  mean=-1.490  max=10.000
奖励 < -5 的比例            : 40.6%
```

（`tools/stability_check.py` 第 10 段用 3000 个种子复测：首步死亡 60.2%，首步奖励均值 -1.306，奖励 < -5 占 39.5%，结论一致。）

用现有 SAC 策略（`sac_triple_final.pt`）跑 200 局：

```
episode 长度  mean=79.7  中位数=1  min=1  max=1000
跑满 1000 步   15/200
第 1 步死亡    124/200
```

对比旧 reset（`init_qpos ± 0.1`）：同样策略 **30/30 局跑满 1000 步**。

### 2.2 物理原因

终止判据是 `tip_y <= 1.5`，而三杆全竖直时 tip 在 `1.8 m`。tip 高度是

```
tip_z = 0.6 · ( cos θ₁ + cos(θ₁+θ₂) + cos(θ₁+θ₂+θ₃) )
```

要让 `tip_z ≥ 1.5`，需要三个余弦之和 ≥ 2.5（最大值 3）。按三杆同向偏离估算，容差只有

```
θ = 0.58 rad (33°)  → tip_z = 1.506  ✓ 刚好活着
θ = 0.60 rad (34°)  → tip_z = 1.486  ✗ 已经判负
```

即**健康区域是「三杆偏离不超过约 0.58 rad」的极小邻域**。而新 reset 的两个分支都远远超出：

- **大角度分支 `uniform(-1.2, 1.2)`**：三杆都取 1.2 rad 时
  `tip_z = 0.6·(cos1.2 + cos2.4 + cos3.6) = 0.6·(0.362 − 0.737 − 0.897) = −0.763 m`，必然判负。实测该分支 86.7% 首步死亡。
- **下垂分支 `θ₁ = π`**：`tip_z = 0.6·(−1 −1 −1) = −1.8 m`，**100% 首步死亡**。

### 2.3 后果

40% 的 episode 是「单步、奖励恒为 −12.96」的样本。后果有三层：

1. **样本效率崩塌**：batch 里约 60% 是零信息的单步轨迹，critic 学不到任何控制信息。
2. **奖励分布被污染**：40.6% 的样本奖励 < −5，而正常平衡的瞬时奖励在 10 附近。这个双峰分布会让值函数拟合困难。
3. **设计意图落空**：注释写的「自然下垂 / 大角度随机」看起来是想做课程学习或全局恢复，但判据不允许 episode 活过第一步，**根本没有机会去恢复**。

### 2.4 修正方向（已验证）

把 `termination_height` 放宽到 `-2.0`（让 tip 能垂到地上也不终止），用同一个旧策略复测 200 局：

```
termination_height=1.5  : len mean=  79.7  med=    1  曾把 tip_y 恢复到 ≥1.7 的局数  62/200
termination_height=-2.0 : len mean=1000.0  med= 1000  曾把 tip_y 恢复到 ≥1.7 的局数 167/200
```

**结论：从任意姿势恢复本身是可行的，唯一挡住它的是终止判据。**连这个只在竖直附近训练过的旧策略都能在 83.5% 的局里把 tip 拉回 1.7 以上。

所以正确做法是改判据而不是去掉大角度分支，三种可选方案：

| 方案 | 做法 | 代价 |
|------|------|------|
| A. 放宽判据 | `termination_height=-2.0`（或 `-1.9`），靠奖励项拉回目标高度 | 奖励地形变平，需配合 `distance_penalty` 权重调整 |
| B. 角度判据 | 用「三杆偏离角超限」而非 tip 高度判负 | 与现有 `tip_y` 版本不兼容，需重训 |
| C. 分级课程 | 保留大角度但降低比例（如 5%），并把判据放宽 | 改动最小，但样本仍然偏斜 |

如果坚持保留 `termination_height=1.5`，那大角度/下垂分支必须**删除**，否则等于往缓冲池里灌 60% 的噪声。

## 3. 训练 / 评估口径不一致（第 2 节的直接后果）

当前代码库里各入口构造环境的参数已经分叉：

| 入口 | `reset_noise_scale` | `termination_height` |
|------|--------------------|---------------------|
| `algorithms/sac/sac_train.py:75` | 0.05（**已失效**） | **−999（永不终止）** |
| `algorithms/ppo/train.py:51` | 0.05（**已失效**） | 默认 1.5 |
| `evaluation/viz.py:198` | 0.05（**已失效**） | −999 |
| `eval_sac.py:9` | 0.05（**已失效**） | 默认 **1.5** |
| `examples/demo_random.py:74` | 默认 | 默认 1.5 |
| `examples/train_sb3.py:40` | 默认 | 默认 1.5 |

三个后果：

**3.1 `eval_sac.py` 会全盘报 FAIL。** 实测输出：

```
Episode 01:    9 steps |  0.45 s | FAIL
Episode 02:    1 steps |  0.05 s | FAIL
...
Episode 20:    1 steps |  0.05 s | FAIL      (20/20 FAIL, 最长 11 步)
```

这不是策略退化。同一个 `sac_triple_final.pt` 在旧 reset 下 30/30 局跑满 1000 步、tip_y 最低 1.758。它现在报 FAIL 的唯一原因是：**评估脚本用默认 `termination_height=1.5`，而新 reset 有 60% 的初始状态本来就低于 1.5**，第 1 步必然判负。评估口径和训练口径对不上。

**3.2 PPO 与 SAC 在训练的任务定义已经不同。** SAC 用 `termination_height=-999`（永不终止），PPO 用默认 `1.5`（会终止）。这两个不是同一个 MDP：终止条件改变了回报的折扣结构和 episode 长度分布。**此时再做 PPO vs SAC 的性能对比，前提已经不成立**，README 里若保留这类对比曲线需要重新说明或重跑。

**3.3 `termination_height=-999` 本身也有代价。** 它把「跌倒」这个信息彻底删除，而终止信号本身是有用的学习信号。副作用是：新 reset 那 40% 下垂分支现在会跑满 1000 步，每步奖励约

```
alive_bonus − (tip_y − 1.8)²  =  10 − (−1.8 − 1.8)²  =  10 − 12.96  ≈  −2.96
```

即每局累积约 −2960 的回报。这类「物理上极难恢复」的 episode 占 40%，会把 critic 拉向悲观，并让 alive bonus 在一个根本无法维持平衡的状态上照常发放。

建议统一口径：给 `InvertedTriplePendulumEnv` 的默认值定一套口径（例如统一 `termination_height=-2.0`、把终止条件下沉到 env 默认值），让所有入口不传这个参数，只在显式的消融实验里覆盖。**至少先让 `eval_sac.py` 与训练用同一套参数**，否则它的 PASS/FAIL 结论没有意义。

## 5. 物理仿真本身：9/9 通过

`tools/stability_check.py` 输出（`python tools/stability_check.py`）：

### 5.1 能量无源性 —— 无能量注入

零动作 rollout 100 秒，逐步统计总能量（动能 + 势能）变化：

```
E(t=0)=100.9235 J  ->  E(t=100 s)=-100.5699 J   (势能参考点在小车高度，故为负)
单步最大能量增量 = -3.476e-07 J
```

阻尼 0.05 存在于每个自由度上，所以每一步 `ΔE` 必须 ≤ 0。实测**最大单步增量为负**，说明 RK4 没有制造能量——这是判断显式积分器是否失稳最直接的证据。

### 5.2 时间步裕度 —— 6×

同样的 60 秒剧烈随机驱动（±1 满量程、每 7 个物理步换一次），扫描 RK4 时间步：

```
dt=0.02    peak|qvel| =   63.4    ok
dt=0.04    peak|qvel| =   50.5    ok
dt=0.05    peak|qvel| =   53.5    ok
dt=0.055   peak|qvel| =   48.5    ok
dt=0.06    peak|qvel| = 1.37e18   *** 发散 ***
dt=0.08    peak|qvel| = 1.22e25   *** 发散 ***
dt=0.1     peak|qvel| = 1.86e60   *** 发散 ***
```

RK4 的稳定边界在 `dt ≈ 0.055~0.06`，出厂 `dt=0.01` 有 **6 倍裕度**。

对训练速度的意义：`docs/SAC_SPS_SPEEDUP.md` 里关心 SPS。如果打算靠加大物理步长提速，`dt` 提到 `0.02~0.05`（2~5 倍）仍安全，`0.06` 以上直接炸。但注意 `frame_skip` 是控制周期与物理步长的比值，单改 `dt` 会改变控制频率，需要同步调 `frame_skip` 才能保持 20 Hz 控制。

### 5.3 时间步收敛性 —— dt=0.01 已在渐近区

同一初值，2 秒零动作，以 `dt=0.001` 为基准：

```
dt=0.02    max|err| = 3.932e-02 rad
dt=0.01    max|err| = 9.595e-04 rad
dt=0.005   max|err| = 2.733e-05 rad
dt=0.002   max|err| = 5.103e-07 rad
每次减半的观测收敛阶: 5.4 / 5.1 / 5.7
```

误差随 dt 减小严格按幂律下降，`dt=0.01` 处轨迹误差 `9.6e-4 rad`（约 0.05°）。这个 2 秒窗口是刻意选的：更长的窗口里混沌会把截断误差放大成轨迹完全去相关，那时测到的就不再是积分误差。

### 5.4 积分器阶数 —— 出厂选 RK4 是对的

以 `RK4@dt=1e-4` 为基准，1 秒窗口：

```
积分器          err@0.01     err@0.005    比值    观测阶
RK4            2.1172e-04    1.5327e-05   13.81    3.79
EULER          2.4072e-01    1.0878e-01    2.21    1.15
IMPLICITFAST   2.4072e-01    1.0878e-01    2.21    1.15
IMPLICIT       1.0964e-01    6.0095e-02    1.82    0.87
```

MuJoCo 的 `EULER` / `implicit` / `implicitfast` 全都是**一阶**方法（implicit 系列用稳定性换精度，还引入数值阻尼），只有 `RK4` 是四阶。同一 `dt=0.01` 下 RK4 的误差比一阶方法小约 **1140 倍**（`2.1e-4` vs `2.4e-1`）。

这条值得写进答辩材料：**为什么用 RK4 而不是 MuJoCo 默认的 implicitfast**——因为本模型只有 1 个约束（导轨限位）且没有接触，刚性来自力矩而非硬接触，RK4 的稳定性代价可以接受，而精度收益是三个数量级。上游 Gymnasium 的 `InvertedDoublePendulum-v5` 同样用 RK4，此处保持一致。

### 5.5 平衡点无漂移 —— 无伪不对称

```
精确竖直 qacc = [0. 0. 0. 0.]
tip_z: 1.800000000000000 -> 1.800000000000000   100 秒漂移 = +0.000e+00 m
max|qvel| = 0.000e+00
```

在鞍点上 100 秒零漂移，说明模型完全对称、积分器没有注入伪力。顺带一提，上游 Gymnasium 的双摆 XML 用 `gravity="1e-5 0 -9.81"` 故意破坏对称来避免落在精确鞍点上，本项目用 `0 0 -9.81`，在鞍点上反而更干净。

### 5.6 鞍点发散率 —— 装置的固有难度

从不同初始倾角 `d`（三杆同时偏 `d`）自由下落，测 tip 掉到 1.5 的时间：

```
d = 1e-01 rad  ->  0.500 s
d = 1e-02 rad  ->  0.800 s
d = 1e-03 rad  ->  1.000 s
d = 1e-04 rad  ->  1.200 s
d = 1e-05 rad  ->  1.400 s
d = 1e-06 rad  ->  1.600 s

发散率 λ ≈ 11.51 s⁻¹   ->   时间常数 τ ≈ 87 ms
初始误差每多一个数量级，只多换来 200 ms 的恢复时间
控制周期 0.05 s 相当于 0.58 个时间常数
```

用 RK4 精化 20 倍（`dt=0.0005`）复测，落时间**完全一致（偏差 0 ms）**，证明 λ=11.51 是装置的物理属性，不是离散化伪影。

这几个数字对答辩很有用：

- τ = 87 ms 说明这是一个**快变不稳定系统**，控制周期 50 ms 已经接近时间常数，几乎没有留白；
- 每多一个数量级的初始偏差只换来 200 ms，说明**误差预算极其紧张**——这也是为什么策略在 reset 噪声从 0.05 提到 0.1 时首步失败率骤升;
- 三阶倒立摆的难点不在「力矩不够」（最大静态加速度 21.3 m/s²），而在**可用时间太短**。

### 5.7 长时强驱动 —— 无 NaN

20 万物理步（= 2000 秒仿真时间），每 7 步随机换一次 ±1 满量程控制：

```
max|qpos| = 976.6 rad   max|qvel| = 112.9   max|qacc| = 7615   max|qfrc_constraint| = 16868
导轨限位越界 = 0.00e+00 m
MuJoCo 求解器警告 = 0
```

关节角度累积到 976 rad 是正常的（三根自由铰链在持续外力泵浦下会不断旋转），无 NaN、无 Inf、求解器零警告。

### 5.8 导轨限位行为

小车限位 `range=[-1, 1]`、`margin=0.01`，用的是 MuJoCo 默认软约束（`solref=[0.02, 1]`）。最恶劣冲击下的穿透量：

```
RK4 @0.01   -> 3.20 cm
RK4 @0.002  -> 3.87 cm      精化后收敛到 ≈3.9 cm
IMPLICITFAST @0.002 -> 3.90 cm
```

三种积分器在精化后收敛到同一穿透量 `≈3.9 cm`，说明这是**软约束的正常弹性变形**，不是穿透失稳。策略实际运行中导轨限位从不触发（见下节）。

## 6. 观测空间的两个观察

### 6.1 ±10 裁剪从来不会触发

`_get_obs()` 把 `qvel` 和 `qfrc_constraint` 裁剪到 ±10。实测策略正常运行 20000 步：

```
|qvel| 最大值 = 3.129 (99 分位 0.775)   -> 裁剪不触发
|qfrc_constraint| 最大值 = 0.00         -> 裁剪不触发
小车 |x| 最大值 = 0.841, 触到限位(|x|>0.999) 的步数 = 0/20000
```

所以裁剪逻辑是安全网而非日常工作点，无害。

### 6.2 观测第 11 维恒为零

`qfrc_constraint[0]`（导轨约束力）在策略运行的 20000 步中**恒为 0**——因为小车从不撞到导轨两端。也就是说 12 维观测里有 1 维**零信息量**，纯粹是照搬双摆设计留下的冗余。

这本身不构成稳定性问题，但如果要精简网络输入，这一维是可以去掉的。反过来，如果想让这一维真正起作用，需要缩短导轨或加大 reset 扰动，逼小车贴到限位上。

## 8. 建议的处理顺序

1. **`termination_height` 与 reset 分布必须一起改**（第 2.4 节），并且把评估口径对齐（第 3 节）。当前组合下 60% 的样本是废样本。
2. **决定 `reset_noise_scale` 的去留**（第 4 节）：改回参数驱动，或连同 5 处调用点 + README 一起删干净。
3. 物理内核不要动——积分器、步长、模型几何全部验证通过，改动只会引入新风险。
4. 若改自动力学（XML），重跑 `python tools/stability_check.py`，重点看第 5 节（能量无源性）和第 5.2 节（时间步边界）：这两项任一失败说明积分已不可信。
